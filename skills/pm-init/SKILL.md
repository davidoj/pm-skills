# pm-init — shape the project before planning it

**Serves:** Delegation Readiness, Attention Routing (`PRINCIPLES.md`) — a
project elicited well is a project every later session can reason about.

## The result you're producing

An understanding solid enough to draft a plan from, reached collaboratively:

1. **At least one clear axis** — destination (what they're trying to achieve)
   or mechanism (what they'll actually do). Both vague → keep shaping.
2. **A working vision statement**, synthesized by you, presented as
   provisional. Quality test is *plannability*, not specificity: could you
   say what this person does on a random Tuesday, and tell in a month
   whether it's working?
3. **The load-bearing context surfaced**: real deadlines/forcing functions,
   the bets that might not pay off, assets they're undervaluing, what they
   protect when they can't have everything.

The full playbook — coverage areas, the clarity matrix, probing-suggestion
technique, failure modes, worked examples, capability-horizon anchors during
shaping, reference-case norms, ethical edge cases — is in
[`elicitation.md`](elicitation.md). Read it before starting; it is the skill.

## Hand-offs

- Elicitation complete (user asks, or confirms your summary unchanged) →
  load `pm-plan` and draft.
- Plan approved → create tracker structure per `pm-capture` and the active
  backend (`~/Dev/pm-skills/backends/ACTIVE.md`): a durable root holding the
  plan, initiatives/projects for major milestones, first tasks small.
